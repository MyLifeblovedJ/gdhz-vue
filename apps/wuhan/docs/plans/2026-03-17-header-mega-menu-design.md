# 全局头部统一二级导航设计

## 背景

当前系统头部只有一级导航，用户希望在鼠标移入导航栏时，下拉展示统一的二级导航面板，交互形式参考苹果官网首页。面板不是只展示当前一级项的子菜单，而是一次性展示所有有二级菜单的一级栏目，用户可以直接从统一面板进入任意子项。

## 目标

- 鼠标移入头部导航区域时，展开统一的二级导航面板。
- 面板按一级栏目分组展示所有子菜单。
- 每个分组下的子菜单竖向排列，布局规范、整洁、易扫描。
- 当前没有独立二级页面路由时，点击子菜单先进入对应一级模块页面，并用占位方式标识当前子模块。
- 没有二级菜单的一级导航仍保持现有直接跳转行为。

## 方案

### 1. 导航数据配置化

新增独立导航配置，维护一级导航和其子菜单：

- 首页：无二级菜单
- 风浪潮：漫堤风险、影响评估、应急疏散、应急方案
- 赤潮：无二级菜单
- 海啸：灾情预警、近岸三维模拟、灾害模拟、影响评估
- 咸潮入侵：咸潮观测、咸潮预测
- 海水入侵：入侵现状、入侵预测
- 海平面上升：潮位及概况、灾害模拟、影响评估、数据预测
- 海岸侵蚀：灾害预警、影像分析、侵蚀岸段、下蚀计算、侵蚀分析
- 溢油：无二级菜单

统一配置便于后续把占位二级菜单替换成真实路由。

### 2. 头部统一下拉面板

在 `AppHeader.vue` 中增加一个导航悬停容器：

- 鼠标移入导航区域时打开二级面板。
- 鼠标在导航区域和下拉面板之间移动时保持打开。
- 鼠标离开整个悬停区域后关闭。
- 下拉面板使用统一容器，内部按分组展示所有有二级菜单的一级栏目。

布局采用多列分组，每列包含：

- 一级栏目标题
- 该栏目对应的竖向子菜单列表

### 3. 占位跳转策略

当前不创建真实二级页面路由。点击二级菜单时：

- 跳转到对应一级页面路径
- 附带查询参数 `sub=<submenu-key>`

示例：

- `/sea-condition?sub=overflow-risk`
- `/tsunami?sub=warning`

`Placeholder.vue` 读取查询参数，显示当前一级模块和二级模块名称，例如“海啸 / 灾情预警 开发中”。

风浪潮页已有真实页面，因此其子菜单会进入风浪潮页并保留 `sub` 参数，先作为占位入口。

## 影响范围

- `src/components/layout/AppHeader.vue`
- `src/data/navigation.js`
- `src/views/Placeholder.vue`
- 测试：`src/components/layout/AppHeader.test.js`、新增导航配置测试、占位页测试

## 风险控制

- 不修改现有一级路由结构，避免影响页面装配逻辑。
- 二级菜单全部通过配置渲染，避免在模板中散落硬编码。
- 当前仅增加查询参数，不引入新页面组件，降低回归风险。
